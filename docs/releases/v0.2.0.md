# Termium v0.2.0 — capture and rendering improvements

Changes prepared for v0.2.0. See [GitHub Releases](https://github.com/codr1/termium/releases) for publication status, native archives and the completed validation record.

## Changes since v0.1.1

- Reuse a dedicated browser capture session, remove repeated tab/history discovery from the screenshot path, and skip unchanged viewport updates. Toolbar metadata continues to refresh independently.
- Reduce Sixel band work with exact pixel comparisons, retained short-band scratch storage, and pixel-only encoding that avoids generating and discarding a palette for every dirty band.
- Reuse four bounded frame arenas across Kitty, Sixel and ASCII graphics. Published frames retain ownership until released; newer pending frames replace obsolete work. This reduces allocation traffic while retaining more memory.
- Preserve bundled welcome-page fonts and monospaced logo spacing, including the offline fallback. Avoid displaying the logo before its fonts are ready.
- Add repeatable local performance benchmarks, opt-in CPU/allocation and pipeline diagnostics, and recorded viewport-scaling evidence. Fix the benchmark patch animation's sampling-aliasing failure.
- Clarify Windows WSL2 usage with Windows Terminal and document terminal graphics capabilities.

Performance depends on viewport, page and terminal. Measurements show benefits and tradeoffs, not a universal FPS multiplier: retained memory increases, and some measured latency/throughput results remain mixed. See [OPTIMUS](../../OPTIMUS.md) for the workload-specific evidence.

## Install or update after publication

Close running Termium sessions, then run:

```sh
curl -fsSL https://termium.dev/install | bash
```

After publication this selects the latest release. Until then it still installs the existing release. Check the installed version with `termium --version` (or `~/.local/bin/termium --version`).

Native archives target Linux x86-64, macOS Apple Silicon and macOS Intel. Windows WSL2 uses the Linux archive; this is not a native Windows build. Chromium and Vimium are downloaded and verified during installation. [Platform requirements](../installation.md#platforms-and-limits) apply.

## Research deferred until after this release

CDP streaming, acknowledgement pacing, raw bitmap capture, Electron/CEF experiments and capture-resolution upscaling are **not enabled in the application**. The [research record](../performance/capture-streaming-and-raw-frames.md) explains complete-image CDP payloads, the standalone measurements, and the next experiments. The screenshot capture path and current renderer defaults remain in use.

Release qualification and its earlier environment restrictions are recorded in the [preparation log](v0.2.0-preparation.md). The GitHub release records the final archive and upgrade checks; earlier branch results are not a substitute for validation of the combined source.
